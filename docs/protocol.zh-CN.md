# QS668 AI录音卡 BLE 开放协议

这是 QS668 AI录音卡、录音卡的公开 BLE 协议。`website/app.js` 里的测试平台按本文实现。本文没有写出的字段，不要另编。

## BLE UUID

| 用途 | UUID | 方向 |
| --- | --- | --- |
| 主服务 | `0000ae20-0000-1000-8000-00805f9b34fb` | 发现服务 |
| 写入特征 | `0000ae21-0000-1000-8000-00805f9b34fb` | 主机写入设备 |
| 通知特征 | `0000ae22-0000-1000-8000-00805f9b34fb` | 设备通知主机 |
| 按键/机身事件通知 | `0000ae23-0000-1000-8000-00805f9b34fb` | 设备通知主机 |

## 协议帧格式

```text
偏移  长度  字段       说明
0     1     HEADER     固定 0x5A
1     1     SEQ        序号，0xFF 后回绕
2     2     CRC        CRC-16/XMODEM，小端
4     2     LEN        负载长度，小端
6     LEN   PAYLOAD    TYPE CMD PARAMS...
```

负载格式：

```text
TYPE CMD PARAMS...
```

CRC 计算范围：

```text
LEN_LO LEN_HI TYPE CMD PARAMS...
```

CRC 算法：CRC-16/XMODEM，多项式 `0x1021`，初始值 `0x0000`。

标准校验向量：

```text
crc16Xmodem("123456789") = 0x31C3
```

## 命令分组

| TYPE | 分组 |
| --- | --- |
| `0` | 设备控制与状态 |
| `1` | 实时音频 |
| `2` | 文件列表、导入、删除 |
| `3` | 录音控制与录音状态 |

## 常用命令

### TYPE 0：设备控制

| 请求 | 含义 | 说明 |
| --- | --- | --- |
| `0-0` | 同步时间 | 参数：年低位、年高位、月、日、时、分、秒 |
| `0-1` | 获取容量 | 响应 `0-2`，剩余 KB 和总 KB，小端 u32 |
| `0-3` | 获取电量 | 响应 `0-4`，百分比；`110` 表示充电中 |
| `0-10` | 获取固件版本 | 响应 `0-11`，文本 |
| `0-12` | 获取授权码 | 响应 `0-13`，ASCII/HEX |

### TYPE 1：实时音频

| 请求 | 含义 |
| --- | --- |
| `1-0` | 开始实时音频 |
| `1-2` | 结束实时音频 |
| `1-3 01` | 暂停实时音频 |
| `1-3 00` | 继续实时音频 |

设备应答：

| 应答 | 含义 |
| --- | --- |
| `1-0` | 本次文件名，推流前发出 |
| `1-1` | 原始 OPUS 负载。每包 40 字节，20 ms 一帧 |
| `1-4` | 状态：`0` 继续，`1` 暂停，`2` 停止 |

把 `1-1` 的负载按顺序拼成文件后，用 `tools/qs668-raw-opus-to-ogg.py` 包成 Ogg/Opus 再播放。转写不是本协议的一部分。

### TYPE 2：文件

| 请求 | 含义 |
| --- | --- |
| `2-0` | 读取文件列表 |
| `2-2` | 从设备导入/下载文件 |
| `2-7` | 终止导入 |
| `2-8` | 删除单个文件 |
| `2-9` | 删除全部文件 |
| `2-12` | 分段导入 |

文件列表中的整数使用大端：

```text
COUNT_BE32
ENTRY...

ENTRY:
duration_or_time_BE32
size_BE32
filename_fixed_20_bytes
```

`2-2` 导入请求参数：

```text
offset_LE32 + filename_fixed_24_bytes
```

设备应答：

| 应答 | 含义 |
| --- | --- |
| `2-1` | 列表数据。`count` 是本帧条目数，不是总文件数 |
| `2-3` | 开始导入，正文为实际文件名 |
| `2-4` | 文件数据分片，按到达顺序拼接 |
| `2-5` | 结束。`0` 完成，`1` 文件不存在，`2` 偏移过大，`3` 其他停止 |
| `2-10` | 删除全部结果。`0` 成功，`1` 失败；旧固件可能不发 |
| `2-11` | 终止导入应答 |
| `2-13` | 删除单个结果。`0` 成功，`1` 失败；旧固件可能不发 |
| `2-18` | 列表发送完毕，正文 `0` 表示完成 |

`2-8` 的参数是列表里的那条 28 字节原始记录。`2-12` 的参数是 `start_LE32 + end_LE32 + 文件名`。

列表可能分多帧到达。收齐后应等到 `2-18`。旧固件不发 `2-18` 时，最后一帧之后空闲约 1.2 秒可以把已收到的条目当作列表。

列表文件名固定 20 字节，超长时会截断扩展名。`note20260710-162938.opus` 在列表中是 `note20260710-162938.`。导入前要补回扩展名：先试 `.wav`，失败再试 `.opus`，最后才用列表里的原始截断名。请求里的文件名固定 24 字节，不足补 `0`。

`2-2` 的完整帧是 36 字节，必须一次 GATT 写入 AE21。把这一帧拆成 20 字节加 16 字节时，设备会把文件名解析错，并回 `2-5` / `1`（文件不存在）。

收到 `2-3` 后开始拼接 `2-4`。每次收到数据可把空闲计时重置。约 12 秒没有数据则超时。已经收到字节后再超时，不要改文件名重试。结束码 `1` 且尚未收到数据时，才换下一个候选文件名。结束码 `0` 时保存文件。请求 `.wav` 且文件头为 `RIFF` / `WAVE` 时，按 WAV 验收：声明长度等于实际长度。列表中的 `size` 是卡内体积，不等于转码后的 WAV 大小。

### TYPE 3：录音

| 请求 | 含义 |
| --- | --- |
| `3-1` | 开始录音 |
| `3-3` | 保存录音 |
| `3-5` | 暂停录音 |
| `3-7` | 继续录音 |
| `3-19` | 获取录音状态 |
| `3-21` | 获取录音时长和当前大小 |
| `3-23` | 获取当前文件名 |
| `3-25` | 获取增益 |
| `3-27` | 设置增益 |

设备应答使用请求号加 1。开始、保存、暂停、继续的结果字节：`1` 成功，`2` 失败。设置增益的结果字节：`0` 成功，`1` 失败。

| 应答 | 含义 |
| --- | --- |
| `3-20` | 录音状态：`1` 录音中，`2` 未录音，`3` 暂停 |
| `3-22` | 时长为小端 u16 秒，当前大小为小端 u32 字节 |
| `3-24` | 当前文件名 |
| `3-26` | 增益：`1` 低，`2` 中，`3` 高 |

`AE23` 用命令号 `1` / `3` / `5` / `7` 上报机身开始、保存、暂停、继续。AE22 与 AE23 必须各自组帧，不能共用一个字节缓存。

## 接收兼容

发送帧始终计算 CRC-16/XMODEM。接收时，CRC 相符则接受。个别录音手表固件的列表帧把 CRC 固定为 `0x0000`，但 LEN 与负载仍然有效；这种帧可以解析，并记一条警告。CRC 既不是计算值也不是 `0x0000` 时丢弃该帧。长度超过 8192 的帧视为无效。
